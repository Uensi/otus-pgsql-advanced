## 2026.10.17 — DBA-функции и сквозное тестирование

### Новые возможности
- **Риски** (новый экран): wraparound XID/MultiXact с прогнозом до остановки записи и
  VACUUM FREEZE в фоне; RPO — возраст бэкапов, архивация WAL, очередь `.ready`;
  автоматическая проверка восстановления из бэкапа (агент, команда `restore_test`);
  слоты по `wal_status`/удерживаемому WAL; лаг реплик в секундах. Риски — в сводке
  здоровья кластера и в новых правилах алертов.
- **Активные сессии (ASH)**: ежесекундная выборка `pg_stat_activity`, график AAS по классам
  ожиданий, топ ожиданий/запросов/пользователей/баз.
- **Производительность**: история `pg_stat_statements` и поиск регрессий; контрольные точки,
  bgwriter и WAL с рекомендациями; прогресс долгих операций (`pg_stat_progress_*`).
- **Аудит индексов**: невалидные, дубли, перекрытые, FK без индекса, неиспользуемые + SQL.
- **Журналы PostgreSQL** через агента (`log_tail`) с разбором на стороне консоли.
- **Аудит безопасности** (оценка 0–100) и **помощник обновлений** (минорные версии, EOL,
  проверки перед pg_upgrade, план для Patroni); `tools/update_pg_versions.py`.
- **LDAP / Active Directory** с ролями по группам (в т.ч. вложенным).
- **Еженедельный отчёт**: страница для печати/PDF и рассылка по расписанию.

### Исправлено по итогам E2E на живом кластере (Patroni 4 + PostgreSQL 16 + wal-g 3)
- Дельта-бэкапы всегда были полными: у `wal-g backup-push` флаг `-f` — это `--full`.
- Консоль не отличала полный бэкап от дельты: `backup-list` без `--detail`, а wal-g 3.x не
  отдаёт `is_full` вовсе — тип теперь определяется по имени (`_D_`).
- Дельта с реплики падала («Finish LSN … greater than current LSN») без новой точки
  рестарта — агент делает CHECKPOINT на реплике и повторяет, иначе понятная ошибка.
- Обычный restore создавал каталог, который не запускался (не было `restore_command` и
  `recovery.signal`). Теперь — восстановление до точки согласованности.
- Восстановленные копии (restore/PITR/клон) наследовали `archive_command` и при запуске
  писали бы WAL новой линии времени в хранилище боевого кластера — теперь `archive_mode = off`.
- `pg_controldata` в инспекции клона не находился (шаблон пути `*` не раскрывался).
- Агент подключался к PostgreSQL только по 127.0.0.1 — теперь адрес из `postgresql.listen`.
- pg_dump и wal-g можно запускать без root (`PATRONI_AGENT_NONROOT=1`) — для контейнеров.


## 2026.10.17

### Интерфейс: обновление без мерцания
- Новый `static/ui-kit.js`: morph-обновление DOM вместо `innerHTML` (111 мест). При опросе
  меняются только изменившиеся узлы — таблицы, карточки и ленты не перерисовываются.
- Повторный опрос больше не подменяет данные на «загрузка…» (хосты, слоты, блокировки,
  базы): скелет показывается только при первом открытии экрана.
- Списки switchover/failover, нода метрик, SQL-консоли, бэкапов и др. больше не сбрасывают
  выбор пользователя каждые 3 секунды (`syncSelect`).
- Графики обновляют точки в существующих наборах данных — легенда и цвета не пересоздаются.
- Журнал добавляет строку, а не перестраивает весь HTML; убран мигающий счётчик запросов.
- Числа моноширинные, полоса прокрутки зарезервирована — ничего не «прыгает».
- Повторные запросы одного URL переиспользуют промис (раньше второй вызов получал `null`
  и мог показать «ошибка» на секунду).
- Порог алерта: обработчик навешивается один раз (раньше с каждым опросом — дубли запросов).
- DCS опрашивается раз в 15 с, а не на каждом тике кластера (3 с).

### Понятность для DBA
- Сводка здоровья кластера с причинами; учёт состояния `streaming` (Patroni 3.x — раньше
  здоровые реплики отображались красным как «не running»).
- Подсказки к колонкам и метрикам, русские названия состояний и метрик DBA.
- Подтверждения с описанием последствий; failover/reinit/рестарт кластера — ввод имени.
- Уведомления о результате операций (раньше restart/reload/reinit молчали).
- Экран в адресной строке, тема по системной настройке.

### Безопасность
- `/api/agent/status` (бэкапы, метрики всех узлов) был доступен без входа — закрыт.
- CSRF-защита по `Sec-Fetch-Site`/`Origin`, заголовки CSP/X-Frame-Options/nosniff/HSTS.
- Новая сессия при входе (защита от фиксации), X-Forwarded-For — только при `trust_proxy`.
