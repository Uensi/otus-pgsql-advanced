# Домашнее задание N11: Кластеры высокой доступности

## Информация о проекте

| Параметр | Значение |
|---|---|
| Название проекта | `bananaflow-30081986` |
| Дата выполнения | 2026-08-08 |
| Версия PostgreSQL | 18.4 |
| Версия Patroni | latest (pip) |
| Версия etcd | 3.5.14 |
| Версия HAProxy | пакет Ubuntu 22.04 |
| Инфраструктура | Terraform (Yandex provider 0.215.0) |
| Автоматизация | Ansible |


## 1. Цель

Развернуть высокодоступный кластер PostgreSQL в Yandex Cloud с использованием стека
**Patroni + etcd + HAProxy + Yandex Network Load Balancer**, обеспечить автоматический
failover при падении ноды и подтвердить работоспособность кластера логами и тестом отказа.

---

## 2. Архитектура решения

```text
                        Клиент (psql)
                             │
                             ▼
                 ┌───────────────────────┐
                 │  Yandex NLB (L4)      │  внешний IP, порт 5432
                 │  healthcheck TCP 5000 │
                 └───────────┬───────────┘
              ┌──────────────┼──────────────┐
              ▼              ▼              ▼
        ┌───────────┐  ┌───────────┐  ┌───────────┐
        │ ha-pg-01  │  │ ha-pg-02  │  │ ha-pg-03  │
        │ zone-a    │  │ zone-b    │  │ zone-d    │
        │ PostgreSQL│  │ PostgreSQL│  │ PostgreSQL│
        │ Patroni   │  │ Patroni   │  │ Patroni   │
        │ etcd      │  │ etcd      │  │ etcd      │
        │ HAProxy   │  │ HAProxy   │  │ HAProxy   │
        └───────────┘  └───────────┘  └───────────┘
              ▲              ▲              ▲
              └──── etcd quorum (3 ноды) ───┘
```

| Компонент | Назначение |
|---|---|
| **Patroni** | оркестратор PostgreSQL: репликация, выборы лидера, авто-failover |
| **etcd** | DCS: хранит состояние кластера, обеспечивает quorum |
| **HAProxy** | L7-маршрутизация: 5000 --> Leader, 5001 --> Replica (через REST Patroni `/primary`, `/replica`) |
| **Yandex NLB** | единая внешняя точка входа + healthcheck, исключает мёртвые ВМ |

| Нода | Зона | Private IP |
|---|---|---|
| `ha-pg-01` | `ru-central1-a` | 10.1.0.31 |
| `ha-pg-02` | `ru-central1-b` | 10.1.1.23 |
| `ha-pg-03` | `ru-central1-d` | 10.1.2.32 |

Нечётное число нод обеспечивает кворум etcd при падении одной ноды/зоны.

## 3. Стенд и системные условия

| Параметр | Значение |
|---|---|
| Облако / зоны | Yandex Cloud, `ru-central1-a`, `ru-central1-b`, `ru-central1-d` |
| ВМ | 3 идентичные: `ha-pg-01`, `ha-pg-02`, `ha-pg-03` |
| CPU / RAM | 2 vCPU / 4 GB RAM (каждая ВМ) |
| Диск | 32 ГБ, network-ssd |
| ОС | Ubuntu 22.04 LTS |
| СУБД | PostgreSQL 18.4 (PGDG) |
| Сеть | подсети 10.1.0.0/24, 10.1.1.0/24, 10.1.2.0/24; SSH — только с моего IP |

**PostgreSQL (через Patroni bootstrap):** `shared_buffers=1GB`, `max_connections=200`,
`wal_level=replica`, `max_wal_senders=10`, `max_replication_slots=10`, `hot_standby=on`, `use_pg_rewind=true`.

**Patroni:** `ttl=30`, `loop_wait=10`, `retry_timeout=10`, `maximum_lag_on_failover=1MB`, REST API :8008.

## 4. Инфраструктура: Terraform

### `providers.tf`

```hcl
terraform {
  required_version = ">= 1.3.0"

  required_providers {
    yandex = {
      source  = "yandex-cloud/yandex"
      version = "0.215.0"
    }
  }

  cloud_id  = var.yandex_cloud_id
  folder_id = var.yandex_folder_id
  token     = var.yandex_token
}
```

### `variables.tf`

```hcl
variable "yandex_cloud_id" { type = string }
variable "yandex_folder_id" { type = string }
variable "yandex_token" { type = string sensitive = true }

variable "yandex_zones" {
  type    = list(string)
  default = ["ru-central1-a", "ru-central1-b", "ru-central1-c"]
}

variable "my_ip" { type = string }
variable "vm_user" { type = string default = "ubuntu" }
variable "ssh_public_key" { type = string }
variable "vm_count" { type = number default = 3 }
variable "vm_platform_id" { type = string default = "standard-v3" }
variable "vm_cores" { type = number default = 2 }
variable "vm_memory" { type = number default = 4 }
variable "vm_disk_size" { type = number default = 32 }
variable "vm_disk_type" { type = string default = "network-ssd" }
```

### `locals.tf`

```hcl
locals {
  my_ip_cidr = length(regexall("/", var.my_ip)) > 0 ? var.my_ip : "${var.my_ip}/32"

  # 10.1.0.0/22 покрывает 10.1.0.0/24, 10.1.1.0/24 и 10.1.2.0/24
  internal_cidr = "10.1.0.0/22"

  ssh_port           = 22
  pg_port            = 5432
  patroni_port       = 8008
  haproxy_rw_port    = 5000
  haproxy_ro_port    = 5001
  haproxy_stats_port = 7000
}
```

### `main.tf`

```hcl
# =====================================================
# Сеть: по подсети в каждой зоне
# =====================================================
resource "yandex_vpc_network" "ha_network" {
  name = "ha-network-yc"
}

resource "yandex_vpc_subnet" "ha_subnet" {
  count = length(var.yandex_zones)

  name       = "ha-subnet-${var.yandex_zones[count.index]}"
  zone       = var.yandex_zones[count.index]
  network_id = yandex_vpc_network.ha_network.id

  v4_cidr_blocks = ["10.1.${count.index}.0/24"]
}

# =====================================================
# Security groups
# =====================================================
resource "yandex_vpc_security_group" "ha_internal_sg" {
  name       = "ha-internal-sg"
  network_id = yandex_vpc_network.ha_network.id

  ingress {
    protocol       = "ANY"
    description    = "All traffic inside cluster subnets"
    v4_cidr_blocks = [local.internal_cidr]
  }

  egress {
    protocol       = "ANY"
    v4_cidr_blocks = ["0.0.0.0/0"]
  }
}

resource "yandex_vpc_security_group" "ha_vm_sg" {
  name       = "ha-vm-sg"
  network_id = yandex_vpc_network.ha_network.id

  ingress {
    protocol       = "TCP"
    description    = "SSH from my IP"
    v4_cidr_blocks = [local.my_ip_cidr]
    port           = local.ssh_port
  }

  ingress {
    protocol       = "ICMP"
    v4_cidr_blocks = [local.my_ip_cidr]
  }

  # NLB не поддерживает security groups, поэтому порты HAProxy
  # открыты для healthcheck'ов балансировщика
  ingress {
    protocol       = "TCP"
    description    = "HAProxy rw/ro for NLB traffic and healthchecks"
    v4_cidr_blocks = ["0.0.0.0/0"]
    from_port      = local.haproxy_rw_port
    to_port        = local.haproxy_ro_port
  }

  ingress {
    protocol       = "TCP"
    description    = "HAProxy stats from my IP"
    v4_cidr_blocks = [local.my_ip_cidr]
    port           = local.haproxy_stats_port
  }

  egress {
    protocol       = "ANY"
    v4_cidr_blocks = ["0.0.0.0/0"]
  }
}

# =====================================================
# 3 ВМ — по одной в каждой зоне
# =====================================================
data "yandex_compute_image" "ubuntu" {
  family    = "ubuntu-2204-lts"
  folder_id = "standard-images"
}

resource "yandex_compute_instance" "ha_pg" {
  count = var.vm_count

  name        = "ha-pg-0${count.index + 1}"
  platform_id = var.vm_platform_id
  zone        = var.yandex_zones[count.index]

  allow_stopping_for_update = true

  resources {
    cores  = var.vm_cores
    memory = var.vm_memory
  }

  boot_disk {
    initialize_params {
      image_id = data.yandex_compute_image.ubuntu.id
      size     = var.vm_disk_size
      type     = var.vm_disk_type
    }
  }

  network_interface {
    subnet_id = yandex_vpc_subnet.ha_subnet[count.index].id
    nat       = true
    security_group_ids = [
      yandex_vpc_security_group.ha_internal_sg.id,
      yandex_vpc_security_group.ha_vm_sg.id,
    ]
  }

  metadata = {
    ssh-keys           = "${var.vm_user}:${trimspace(var.ssh_public_key)}"
    serial-port-enable = 1
  }
}

# =====================================================
# Yandex Network Load Balancer
# ВАЖНО: у yandex_lb_network_load_balancer нет аргумента
# security_group_ids (его поддерживает только ALB)
# =====================================================
resource "yandex_lb_target_group" "ha_tg" {
  name = "ha-pg-tg"

  dynamic "target" {
    for_each = yandex_compute_instance.ha_pg
    content {
      subnet_id = yandex_vpc_subnet.ha_subnet[target.key].id
      address   = target.value.network_interface[0].ip_address
    }
  }
}

resource "yandex_lb_network_load_balancer" "ha_nlb" {
  name = "ha-pg-nlb"

  listener {
    name        = "pg-rw"
    port        = local.pg_port         # снаружи 5432
    target_port = local.haproxy_rw_port # внутри 5000 (HAProxy rw)
    external_address_spec {
      ip_version = "ipv4"
    }
  }

  attached_target_group {
    target_group_id = yandex_lb_target_group.ha_tg.id

    healthcheck {
      name                  = "hc-haproxy"
      timeout               = 5
      interval              = 10
      healthy_threshold     = 2
      unhealthy_threshold   = 3
      tcp_options {
        port = local.haproxy_rw_port
      }
    }
  }
}
```

### `install_ha.yml`

```yaml
---
- name: Install HA stack (PostgreSQL 18 + Patroni + etcd + HAProxy)
  hosts: ha_cluster
  become: true

  tasks:
    - name: Install base packages
      ansible.builtin.apt:
        name:
          - curl
          - ca-certificates
          - gnupg
          - lsb-release
          - python3-pip
          - haproxy
          - acl
        state: present
        update_cache: true

    - name: Add PostgreSQL apt key
      ansible.builtin.shell: |
        curl -fsSL https://www.postgresql.org/media/keys/ACCC4CF8.asc | gpg --dearmor -o /etc/apt/trusted.gpg.d/pgdg.gpg
      args:
        creates: /etc/apt/trusted.gpg.d/pgdg.gpg

    - name: Add PostgreSQL apt repository
      ansible.builtin.copy:
        dest: /etc/apt/sources.list.d/pgdg.list
        content: "deb http://apt.postgresql.org/pub/repos/apt {{ ansible_distribution_release }}-pgdg main"
        mode: "0644"

    - name: Install PostgreSQL {{ pg_version }}
      ansible.builtin.apt:
        name:
          - postgresql-{{ pg_version }}
          - postgresql-client-{{ pg_version }}
        state: present
        update_cache: true

    # Стандартный кластер PGDG занимает порт 5432 —
    # кластером будет управлять Patroni
    - name: Stop and disable default PostgreSQL service
      ansible.builtin.systemd:
        name: postgresql
        state: stopped
        enabled: false

    - name: Drop default PostgreSQL cluster (free port 5432 for Patroni)
      ansible.builtin.command: pg_dropcluster --stop {{ pg_version }} main
      failed_when: false
      changed_when: false

    - name: Install Patroni via pip
      ansible.builtin.pip:
        name:
          - patroni[etcd3]
          - psycopg2-binary
        state: present

    - name: Create etcd user
      ansible.builtin.user:
        name: etcd
        system: true
        shell: /usr/sbin/nologin
        home: "{{ etcd_data_dir }}"

    - name: Create etcd data directory
      ansible.builtin.file:
        path: "{{ etcd_data_dir }}"
        state: directory
        owner: etcd
        group: etcd
        mode: "0750"

    - name: Download and unpack etcd
      ansible.builtin.unarchive:
        src: "https://github.com/etcd-io/etcd/releases/download/v{{ etcd_version }}/etcd-v{{ etcd_version }}-linux-amd64.tar.gz"
        dest: /tmp
        remote_src: true

    - name: Install etcd binaries
      ansible.builtin.copy:
        src: "/tmp/etcd-v{{ etcd_version }}-linux-amd64/{{ item }}"
        dest: "/usr/local/bin/{{ item }}"
        remote_src: true
        mode: "0755"
      loop:
        - etcd
        - etcdctl

    - name: Create Patroni config directory
      ansible.builtin.file:
        path: "{{ patroni_config_dir }}"
        state: directory
        owner: postgres
        group: postgres
        mode: "0750"
```

### `configure_etcd.yml`

```yaml
---
- name: Configure and start etcd cluster
  hosts: ha_cluster
  become: true

  tasks:
    - name: Create etcd config directory
      ansible.builtin.file:
        path: /etc/etcd
        state: directory
        owner: etcd
        group: etcd
        mode: "0750"

    - name: Render etcd config
      ansible.builtin.template:
        src: templates/etcd.yml.j2
        dest: /etc/etcd/etcd.yml
        owner: etcd
        group: etcd
        mode: "0640"

    - name: Install etcd systemd unit
      ansible.builtin.copy:
        dest: /etc/systemd/system/etcd.service
        mode: "0644"
        content: |
          [Unit]
          Description=etcd key-value store (DCS for Patroni)
          After=network.target

          [Service]
          Type=simple
          User=etcd
          ExecStart=/usr/local/bin/etcd --config-file=/etc/etcd/etcd.yml
          Restart=always
          RestartSec=5
          LimitNOFILE=65536

          [Install]
          WantedBy=multi-user.target

    - name: Reload systemd and start etcd
      ansible.builtin.systemd:
        name: etcd
        state: started
        enabled: true
        daemon_reload: true

    - name: Wait for etcd endpoint to be healthy
      ansible.builtin.shell: |
        etcdctl endpoint health --endpoints=http://{{ private_ip }}:{{ etcd_client_port }}
      register: etcd_health
      until: etcd_health.rc == 0
      retries: 12
      delay: 5
      changed_when: false
```

### `configure_patroni.yml`

```yaml
---
- name: Configure and start Patroni
  hosts: ha_cluster
  become: true
  serial: 1   # первая нода становится Leader, остальные клонируются в Replica

  tasks:
    - name: Render Patroni config
      ansible.builtin.template:
        src: templates/patroni.yml.j2
        dest: "{{ patroni_config_dir }}/patroni.yml"
        owner: postgres
        group: postgres
        mode: "0640"

    - name: Install Patroni systemd unit
      ansible.builtin.copy:
        dest: /etc/systemd/system/patroni.service
        mode: "0644"
        content: |
          [Unit]
          Description=Patroni - PostgreSQL HA orchestrator
          After=network.target etcd.service
          Wants=etcd.service

          [Service]
          Type=simple
          User=postgres
          Group=postgres
          ExecStart=/usr/local/bin/patroni {{ patroni_config_dir }}/patroni.yml
          Restart=always
          RestartSec=5
          TimeoutSec=300

          [Install]
          WantedBy=multi-user.target

    - name: Reload systemd and start Patroni
      ansible.builtin.systemd:
        name: patroni
        state: started
        enabled: true
        daemon_reload: true

    - name: Wait for Patroni REST API to answer
      ansible.builtin.uri:
        url: "http://{{ private_ip }}:{{ patroni_rest_port }}/patroni"
        status_code: 200
      register: patroni_api
      until: patroni_api.status == 200
      retries: 24
      delay: 5
```

### `templates/haproxy.cfg.j2`

```
global
    maxconn 1024
    log /dev/log local0

defaults
    log global
    mode tcp
    option tcplog
    timeout connect 5s
    timeout client  60s
    timeout server  60s

# ---------- WRITE: только на Leader ----------
frontend ft_pg_rw
    bind *:{{ haproxy_rw_port }}
    default_backend bk_pg_rw

backend bk_pg_rw
    option httpchk GET /primary
    http-check expect status 200
    default-server inter 3s fall 3 rise 2 downinter 2s
{% for host in groups['ha_cluster'] %}
    server {{ host }} {{ hostvars[host]['private_ip'] }}:5432 maxconn 200 check port {{ patroni_rest_port }}
{% endfor %}

# ---------- READ: только на Replica ----------
frontend ft_pg_ro
    bind *:{{ haproxy_ro_port }}
    default_backend bk_pg_ro

backend bk_pg_ro
    balance roundrobin
    option httpchk GET /replica
    http-check expect status 200
    default-server inter 3s fall 3 rise 2 downinter 2s
{% for host in groups['ha_cluster'] %}
```

### `failover_test.yml`

```yaml
---
- name: "Шаг 1. Состояние до отказа + запись BEFORE"
  hosts: ha_cluster
  become: true
  tasks:
    - name: Determine node role via Patroni REST
      ansible.builtin.uri:
        url: "http://{{ private_ip }}:{{ patroni_rest_port }}/primary"
        status_code: [200, 503]
      register: role_check

    - name: Set is_leader fact
      ansible.builtin.set_fact:
        is_leader: "{{ role_check.status == 200 }}"

    - name: Create test table and write BEFORE row (leader only)
      ansible.builtin.shell: |
        sudo -u postgres psql -c "CREATE TABLE IF NOT EXISTS failover_test(id serial, written_by text, ts timestamptz DEFAULT now());"
        sudo -u postgres psql -c "INSERT INTO failover_test(written_by) VALUES ('{{ inventory_hostname }}-BEFORE-failover');"
      when: is_leader

    - name: patronictl list (before)
      ansible.builtin.shell: patronictl -c {{ patroni_config_dir }}/patroni.yml list
      register: list_before
      changed_when: false

    - name: Show list (before)
      ansible.builtin.debug:
        msg: "{{ list_before.stdout_lines }}"

- name: "Шаг 2. Останавливаем Patroni на лидере (симуляция отказа)"
  hosts: ha_cluster
  become: true
  tasks:
    - name: Stop Patroni on leader node
      ansible.builtin.systemd:
        name: patroni
        state: stopped
      when: is_leader | default(false)

- name: "Шаг 3. Ждём выборы нового лидера"
  hosts: ha_cluster
  become: true
  tasks:
    - name: Wait until cluster elects a new running Leader
      ansible.builtin.shell: patronictl -c {{ patroni_config_dir }}/patroni.yml list -f json
      register: cl
      until:
        - (cl.stdout | from_json | selectattr('Role', 'equalto', 'Leader') | list | length) == 1
        - (cl.stdout | from_json | selectattr('Role', 'equalto', 'Leader') | first).State == 'running'
      retries: 30
      delay: 5
      changed_when: false

    - name: Show state after failover
      ansible.builtin.shell: patronictl -c {{ patroni_config_dir }}/patroni.yml list
      register: list_after
      changed_when: false

    - name: Print state after failover
      ansible.builtin.debug:
        msg: "{{ list_after.stdout_lines }}"

- name: "Шаг 4. Запись AFTER на новом лидере + чтение всех строк"
  hosts: ha_cluster
  become: true
  tasks:
    - name: Re-check role (не падаем на остановленной ноде)
      ansible.builtin.uri:
        url: "http://{{ private_ip }}:{{ patroni_rest_port }}/primary"
        status_code: [200, 503]
      register: role_check2
      failed_when: false

    - name: Write AFTER row and read table (new leader only)
      ansible.builtin.shell: |
        sudo -u postgres psql -c "INSERT INTO failover_test(written_by) VALUES ('{{ inventory_hostname }}-AFTER-failover');"
        sudo -u postgres psql -c "TABLE failover_test;"
      register: rows_after
      when: role_check2.status | default(0) == 200

    - name: Show rows (должны быть и BEFORE, и AFTER)
      ansible.builtin.debug:
        msg: "{{ rows_after.stdout_lines }}"
      when: role_check2.status | default(0) == 200

- name: "Шаг 5. Возвращаем старый лидер в кластер (станет репликой)"
  hosts: ha_cluster
  become: true
  tasks:
    - name: Start Patroni everywhere (поднимает остановленную ноду)
      ansible.builtin.systemd:
        name: patroni
        state: started

    - name: Wait until old leader rejoins as Replica
      ansible.builtin.uri:
        url: "http://{{ private_ip }}:{{ patroni_rest_port }}/replica"
        status_code: 200
      register: replica_ok
      until: replica_ok.status == 200
      retries: 30
      delay: 5
      when: is_leader | default(false)

- name: "Шаг 6. Финальное состояние, история переключений и логи"
  hosts: ha_cluster
  become: true
  tasks:
    - name: Final patronictl list
      ansible.builtin.shell: patronictl -c {{ patroni_config_dir }}/patroni.yml list
      register: list_final
      changed_when: false

    - name: Show final list
      ansible.builtin.debug:
        msg: "{{ list_final.stdout_lines }}"

    - name: Patroni history (события failover)
      ansible.builtin.shell: patronictl -c {{ patroni_config_dir }}/patroni.yml history
      register: hist
      changed_when: false

    - name: Show history
      ansible.builtin.debug:
        msg: "{{ hist.stdout_lines }}"

    - name: Save patroni/etcd logs for report
      ansible.builtin.shell: |
        mkdir -p /var/ha
        journalctl -u patroni --no-pager -n 500 > /var/ha/patroni_{{ inventory_hostname }}.log
        journalctl -u etcd --no-pager -n 200 > /var/ha/etcd_{{ inventory_hostname }}.log
      changed_when: false

    - name: Fetch logs to control node
      ansible.builtin.fetch:
        src: "/var/ha/{{ item }}_{{ inventory_hostname }}.log"
        dest: "failover_logs/{{ item }}_{{ inventory_hostname }}.log"
        flat: true
      loop:
        - patroni
        - etcd
```

## 8. Тест отказа (failover)

Сценарий: запись BEFORE → остановка Patroni на лидере → выборы → запись AFTER → возврат старой ноды.

### 8.1. До отказа

`ha-pg-01` — Leader (TL 1), реплики streaming, lag 0.

### 8.2. После остановки Patroni на ha-pg-01

```text
| ha-pg-01 | 10.1.0.31 | Replica | stopped   |    |
| ha-pg-02 | 10.1.1.23 | Leader  | running   |  2 |
| ha-pg-03 | 10.1.2.32 | Replica | streaming |  2 |
```

Timeline сменился 1 → 2, новый лидер — `ha-pg-02`.

### 8.3. Целостность данных

```text
 id |        written_by        |              ts
----+--------------------------+-------------------------------
  1 | ha-pg-01-BEFORE-failover | 2026-08-08 17:54:05.137952+00
 34 | ha-pg-02-AFTER-failover  | 2026-08-08 17:54:15.165064+00
(2 rows)
```

Обе строки на месте — данные не потеряны.

### 8.4. История переключений (`patronictl history`)

```text
+----+----------+------------------------------+----------------------------------+------------+
| TL |      LSN | Reason                       | Timestamp                        | New Leader |
+----+----------+------------------------------+----------------------------------+------------+
|  1 | 67619032 | no recovery target specified | 2026-08-08T17:54:09.873864+00:00 | ha-pg-02   |
+----+----------+------------------------------+----------------------------------+------------+
```

### 8.5. Время failover

Остановка лидера 17:54:09 → запись на новом лидере 17:54:15 = **~6 секунд**.

### 8.6. Возврат старой ноды

После `systemctl start patroni` на `ha-pg-01` нода выполнила `pg_rewind` и присоединилась как `Replica | streaming`.

## 10. Проблемы и их решения

| Проблема | Причина | Решение |
|---|---|---|
| `chmod: invalid mode: 'A+user:postgres:rx:allow'` | в образе нет пакета `acl` | установлен `acl`; схема `root + sudo -u postgres` |
| etcd: `yaml: line 11: mapping values are not allowed` | URL в конфиге без кавычек | все URL в шаблоне взяты в кавычки |
| `listener` — set без индексации в outputs | особенность NLB в провайдере | IP получен через `for` expression / `yc` CLI |
| Jinja: `expected token 'end of print statement', got 'qaz'` | пароль внутри `{{ }}` как литерал | пароль вынесен в переменные `group_vars/all.yml` |
| Зона `ru-central1-c` недоступна | ограничения каталога Yandex Cloud | ВМ в зонах `a, b, a` — кворум сохранён |
| Старый лидер остался `stopped` | `set_fact` не живёт между play; `fatal` на REST остановленной ноды | `failed_when: false` + `systemd state=started` на всех нодах |

## 11. Что удобно, что нет

**Patroni + etcd + HAProxy:**
- (+) автоматический failover без ручного вмешательства;
- (+) quorum etcd исключает split-brain;
- (+) REST API Patroni даёт HAProxy точное знание ролей;
- (+) `pg_rewind` — безопасный возврат старого лидера репликой;
- (−) требует аккуратной настройки DCS;
- (−) ручная сборка сложнее Managed-сервиса.

**Yandex NLB:**
- (+) единый внешний IP, встроенный healthcheck;
- (+) автоматически убирает мёртвые ВМ;
- (−) L4: не различает master/replica — нужен HAProxy на нодах.

## 12. Выводы

1. **HA-кластер развёрнут** в Yandex Cloud с распределением по зонам `a` и `b`.
2. **Автоматический failover подтверждён**: ~6 секунд, данные не потеряны, запись продолжилась на новом лидере.
3. **Yandex NLB** балансирует трафик и исключает недоступные ВМ.
4. **Стек Patroni + etcd + HAProxy** переживает падение ноды и (при кворуме) целой зоны.
5. **IaC**: полный цикл воспроизводится `terraform apply` → `ansible-playbook site.yml`.

**Рекомендация:** для продакшна с высоким SLA данный стек — зрелое решение; альтернатива — Yandex Managed Service for PostgreSQL с HA-опцией.
