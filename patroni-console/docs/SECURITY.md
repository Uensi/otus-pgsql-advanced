# Безопасность Patroni Console

## Модель угроз

Консоль может переключать лидера, перезапускать PostgreSQL и менять глобальный конфиг кластера.
Её учётная запись в REST API Patroni равна праву остановить базу. Поэтому:

- консоль ставится в сеть администрирования, а не в пользовательскую сеть;
- доступ только по HTTPS (TLS 1.2+), HTTP консоль не слушает;
- у каждого человека своя учётная запись, общих логинов нет — аудит должен показывать, кто что сделал.

## Что сделано в коде

| Область | Как |
|---|---|
| Аутентификация | Серверные сессии в SQLite (в базе только SHA-256 идентификатора), cookie `__Host-`, `HttpOnly`, `Secure`, `SameSite=Strict`. Простой 2 ч, жёсткий предел 12 ч. Выход удаляет сессию на сервере. Смена роли в конфиге завершает сессии пользователя. |
| Пароли | Только хеши scrypt/pbkdf2; открытый пароль в конфиге не принимается. Сравнение за постоянное время, в том числе для несуществующих логинов. |
| Подбор пароля | Не больше 10 попыток за 15 минут на логин и отдельно на адрес; попытка учитывается до проверки пароля, поэтому параллельные запросы лимит не обходят. Отклонённые по лимиту попытки не пишутся в аудит (база не раздувается). |
| Авторизация | Каждый маршрут обязан объявить минимальную роль; маршрут без объявления отвечает отказом. Роль проверяется на сервере для каждой операции. |
| CSRF | Изменяющие запросы требуют заголовок `X-CSRF-Token`, привязанный к сессии. |
| Браузер | CSP `default-src 'self'`, без inline-скриптов и стилей; HSTS; `X-Frame-Options: DENY`; DOM строится через `textContent`. Тело запроса не больше 64 КБ. |
| Секреты | Только ссылками `${ENV}` в конфиге; файл `/etc/patroni-console/env` с правами 0640 root:patroni-console. Секреты не попадают в ответы API, аудит и логи. В ошибках доставки уведомлений нет ни URL webhook, ни токена бота, ни тела ответа. Роли ниже admin видят глобальный конфиг с замаскированными `recovery_conf`, `standby_cluster` и ключами вида `*password*`, `*conninfo*`, `*command*`. |
| Операции | Проверки перед запуском, ввод имени кластера, одна операция на кластер, однократная отправка без автоповторов. Idempotency-Key привязан к пользователю, роль проверяется до повтора. |
| Глобальный конфиг | Белый список ключей и типов, запрет параметров, которыми управляет Patroni, защита от устаревшего предпросмотра. Параметры, выполняющие команды или загружающие код от имени postgres (`archive_command`, `*_preload_libraries` и т.п.), — только admin с флажком «принудительно». |
| etcd | Только чтение (status, alarm, member list); ключи не читаются и не пишутся. |
| Процесс | systemd: отдельный пользователь, `ProtectSystem=strict`, запись только в `/var/lib/patroni-console`, `NoNewPrivileges`. Файл базы создаётся с правами 0600. HTTP-клиенты не следуют редиректам. |
| Хранение | Аудит хранится 365 дней, события — `watch.keep_days`; просроченные сессии удаляются автоматически. |
| Аудит | Вход, выход, отказы, запуск и итог каждой операции — с пользователем, адресом и request_id. |

## Проверка

Код прошёл ревью безопасности (авторизация, CSRF, сессии, инъекции, XSS, утечки секретов, DoS).
Критичных находок не было; найденные недочёты исправлены и закреплены тестами `tests/test_security.py`.

## Что остаётся за администратором

- Включить `restapi.authentication` на всех нодах Patroni и закрыть порт 8008 файрволом для всех,
  кроме консоли и самих нод.
- Выдать консоли сертификат и ограничить доступ к порту 8443 сетью администраторов.
- Хранить резервные копии `/var/lib/patroni-console/console.db` (там аудит).
- Регулярно менять пароль REST API Patroni и пароли пользователей консоли.
